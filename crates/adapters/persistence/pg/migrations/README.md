# Миграции каталога

Только вперёд: отката нет, ошибку исправляет следующая миграция. Таблицы `package_version`
и `asset` рассчитаны на десятки миллионов строк, поэтому каждая миграция идёт по схеме
expand / migrate / contract и не берёт долгих блокировок.

## Правила

- **Expand.** Новые колонки только nullable (или с константным default), новые таблицы и
  значения enum. Приложение старой версии продолжает работать.
- **Индексы.** Новый индекс на непустой таблице - отдельная миграция с
  `CREATE INDEX CONCURRENTLY` и `no_tx = true` (`Migration::new(.., true)`): внутри
  транзакции CONCURRENTLY не работает. В миграции 0001 таблицы пусты, поэтому там индексы
  обычные.
- **Без переписывания таблиц.** Никакого `ALTER COLUMN .. TYPE` и volatile-default
  (`now()`, `gen_random_uuid()`) в `ADD COLUMN`.
- **NOT NULL задним числом.** Добавить nullable колонку, заполнить пачками отдельным
  шагом (migrate), добавить `CHECK (.. IS NOT NULL) NOT VALID`, затем `VALIDATE CONSTRAINT`,
  и только после релиза, где старого кода уже нет, - contract (`SET NOT NULL`, удаление
  старого).
- **Enum.** Только `ALTER TYPE .. ADD VALUE`; значения не удаляются и не переименовываются.
- **Применённую миграцию не править**: sqlx сверяет контрольную сумму, а правка ломает
  все уже развёрнутые базы. Исправление - новая миграция.

- **Расширения.** Миграции не создают расширений: новое расширение добавляется в `REQUIRED`
  в `src/schema.rs`, `migrate` создаёт и проверяет его до миграций.
- **Документация.** Схема изменилась - обновить рис. 9.3 в `docs/product/09-data-structures.md`.

## Как добавить миграцию

1. Создать `NNNN_описание.sql` в этом каталоге (номер на единицу больше последнего).
2. Зарегистрировать в `src/schema.rs`: ещё один `Migration::new(NNNN, .., include_str!(..), no_tx)`
   в списке `migrator()`.
3. Прогнать `task rust:test:pg`.
