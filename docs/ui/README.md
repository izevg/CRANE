# UI-документация веб-консоли CRANE

Здесь описано, **как устроены экраны**: композиция, блоки, состояния, данные. Как они **выглядят** (цвета, шрифты, радиусы, тени, иконки), задаёт UI kit BRICK (`shared/styles/tokens.css`, `shared/ui/*`), и здесь это не повторяется. Продуктовая архитектура — `docs/product/` (раздел 15 — роли и рабочие столы, 14 — права и журнал); контракт данных — `docs/api/admin.openapi.yaml`.

## Как пользоваться

1. Новый экран: найти его в карте (`screens.md`) → взять архетип (`composition.md` §4) → собрать из паттернов (`patterns.md`) → данные — из ресурсов API, указанных в карте.
2. **MUST** в документах — инварианты (доступность, безопасность отображения, данные, производительность). Отступить можно только с письменным обоснованием fe-lead. **SHOULD** и пометки *мнение* подгоняются под стек без согласования.
3. Макеты Stitch (`mocks/`, локально, не в git) — иллюстрация композиции, а не источник стиля. Ссылки вида `mocks/s7_appsec_light/screen.png` работают только на машине, где лежат макеты.
4. Доступность: цель — **WCAG 2.2 AA**, это MUST (решение владельца 27.10.2026, `decisions.md` D9). Раздел 15 продукта обновлён.
