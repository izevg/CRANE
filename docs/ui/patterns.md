# Паттерны: молекулы и блоки

Каждый паттерн: **зачем** → **анатомия** → **данные** (поля API, согласованные с be-lead) → **состояния** → **доступность** → **из какого макета** (оставлено / исправлено). Компоненты кита указаны в `моноширинном` написании имени; если кит что-то не покрывает, это помечено «пробел кита» и вынесено в `decisions.md`.

Общие правила для всех паттернов:

- **MUST.** Статус никогда не передаётся только цветом: есть текст, у warning и error есть ещё иконка (WCAG 1.4.1).
- **MUST.** Цели нажатия не меньше 24 × 24 CSS px (WCAG 2.2 2.5.8). Исключение — ссылки в строке текста.
- **MUST.** Машинные коды из API (`quarantined`, `P1`, `not_affected`) переводятся в подписи через единый словарь; сырой код показывается только в журнале и диагностике, и там он рядом с подписью.
- **MUST.** Числа — табличные цифры, в таблицах выровнены вправо, форматируются через `Intl` (`ru-RU`): «12 340», «94,2 %», «18,4 ТБ».
- Замеренные контрасты пар токенов (формула WCAG 2.x, 27.10.2026): brand на brand-container 6,89:1; text-hint на muted 4,88:1; warning 4,84:1; error 5,72:1; success 6,49:1; info 5,57:1; dark brand на dark brand-container 5,67:1; dark text-hint на dark muted 4,78:1; граница поля ввода 3,71:1; линия SLO `#D97706` на карточке 3,19:1. Всё проходит AA. Hairline `#E5E6E8` на карточке 1,25:1 — **только декоративная** граница, не граница контрола (1.4.11).

## 1. Заголовок страницы и StatChip

**Анатомия.** `PageHeader`: h1 · StatusBadge · чипы формата и репозитория · caption · ряд `StatChip` («Версий 48», «Последняя 1.4.2») · действия справа (см. `composition.md` §3).

**Правила.**
- StatChip — факт, а не ссылка. Если число ведёт в список, это вкладка со счётчиком, а не чип.
- Не больше 5 чипов; не дублировать то, что уже есть в плитках или вкладках.
- MUST: внутри чипа порядок «подпись → значение» и одна текстовая строка: скринридер читает «Версий 48».

**Из макетов.** S2: ряд чипов — оставлено. S3: иконки в каждом чипе — *мнение*: шум, без иконок. S4: метаданные версии строками с иконками вместо чипов — исправлено на чипы.

## 2. MetricTile (плитка метрики)

**Зачем.** Ответить на «всё ли в порядке» одним взглядом и дать вход в отфильтрованный список.

**Анатомия.** overline-лейбл · значение `metric-xl` + единица · caption (контекст: «старейшая 3 мин», «P1 lodash, P2 axios») · дельта (▲▼ + цвет по «хорошему направлению») · спарклайн 48 px · тон и `toneLabel` при выходе за границу.

**Данные.** Значение `number | null`; `null` → «—» и caption «Нет данных» (MUST: не 0). Для счётчиков со звёздочкой ёмкости — `{count, capped}` → «1 000+».

**Состояния.** загрузка (`MetricTileSkeleton`) · норма · предупреждение (warning-кольцо + `toneLabel` текстом) · критично · нет данных · ошибка опроса (последнее значение + «обновлено 3 мин назад»).

**Задача в кит (решено 27.10.2026).** У `MetricTile` сейчас только тоны `neutral | warning`. В кит BRICK добавляется `tone: "error"` (кольцо error-strong + `toneLabel`) для «P0 открыто», «Цепочка журнала: разрыв», «Просрочено SLA». MUST: `toneLabel` текстом и при этом тоне. До появления в ките — warning-кольцо + `toneLabel` «требует действия».

**Доступность.** Плитка-ссылка — один `<a>` с доступным именем «P0 открыто: 1, требует действия». Спарклайн `aria-hidden`, его смысл дублирует дельта текстом.

**Из макетов.** S6, S7: ряд плиток с caption — оставлено. Плитки-«чипы» в углу («S3 / RAW», «Valkey», «CISA Known Exploited», «9 источников онлайн») — отклонено: второй лейбл в плитке спорит с первым; это caption. Плитка «Системный статус: Норма» — отклонено (дубль). S9: четыре плитки над журналом — оставлено для SecOps.

## 3. Список состояния компонентов (health list)

**Анатомия.** Строка 44 px: имя компонента · caption (метрика: «p95 1,8 мс», «база v2026.10.27», «с 13:42») · StatusBadge справа («Работает», «Деградация», «Недоступен»). Сортировка: сначала проблемные.

**Данные.** `GET /status` → `components[{name, state, latency_ms, since, detail}]`.

**Правила.** MUST: у «Недоступен» есть «с HH:MM» и последствие для пользователя («клиенты получают кэш до 7 дней»). SHOULD: строка — ссылка на экран компонента (E4 Upstream, E13 Интеграции).

**Из макетов.** S6 — оставлено. Кнопка «Журнал инцидентов» — отклонено (в продукте нет такого объекта).

## 4. Графики

Основа — Recharts в токенах кита (палитра графиков из `[1]`).

**Временной ряд.**
- MUST: линии без сглаживания-сплайна, которое рисует несуществующие значения (S2 «Динамика скачиваний», S6 «Запросы и задержки» — исправить). Допустим `monotone` только если он не выходит за экстремумы данных; по умолчанию — `linear`.
- MUST: порог SLO — пунктирная линия `#D97706` с подписью значения у правого края («SLO 150 мс»); контраст с картой 3,19:1.
- Заливка под линией — только для одного ряда; для p50/p95/p99 — три линии без заливок, различимые не только цветом: прямые подписи у конца линии + разный штрих для p99 (WCAG 1.4.1).
- Окно времени задаётся в шапке страницы, ось X — локальное время, в подсказке — полное время и значение.

**Доля (stacked bar, «Объём по командам»).**
- Одна горизонтальная полоса 100 % + легенда-таблица «команда · объём · %» — оставлено из S6, это лучше столбцов из промпта.
- MUST: соседние сегменты разделены зазором 2 px цвета карточки (смежные цвета палитры различаются всего на 1,18–1,29:1), легенда — главный носитель данных.
- Top-8 + «Прочие (N)».
- *Мнение:* убрать пустое пространство под полосой из S6; блок по высоте контента, а не 8/4 «в рост».

**Спарклайн.** Декоративный, `aria-hidden`.

**Доступность.** MUST: каждый график имеет `figure` с заголовком и текстовой сводкой (WCAG 1.1.1) («p95 за 24 ч: 84 мс, максимум 138 мс в 21:40, SLO 150 мс не нарушен») и кнопку «Показать таблицей» (SHOULD). Перерисовка при опросе — без анимации.

## 5. Фасетная панель

**Анатомия.** Карточка с h2 («По форматам») → строки-кнопки: название · число справа · тонкая полоса (доля от максимума). Нажатая строка = активный фильтр (`aria-pressed`).

**Данные.** `facets{format[], workspace[]}` с `{count, capped}`.

**Из макетов.** S1 — оставлено, но фасет «По командам» заменён на «По workspace» (согласовано с API). Карточка «Индекс уязвимостей 99,4 %» — отклонено: неопределённая метрика, похожа на обещание безопасности.

## 6. Карточка результата поиска

**Анатомия (сверху вниз).**
1. Опционально overline «ТОЧНОЕ СОВПАДЕНИЕ» (`exact_match`) или предупреждающий чип (typosquat, устарел) — одна строка, слева.
2. Имя пакета (h3, ссылка на карточку, подсветка совпадения `highlights` — P3) · чип формата · чип «репозиторий · workspace» · справа — пилюля риска («P1 · 1 находка»), если есть.
3. Описание, 1 строка с обрезкой (2 — максимум).
4. Мета: «Последняя 1.4.2» + StatusBadge · «12 340 загрузок за 30 дн» · команда · относительное время · README.

**Правила.**
- MUST: вся карточка не является одной ссылкой с вложенными кнопками; ссылка — имя пакета, остальное — текст. Кнопка «Открыть ↗» в каждой карточке (S1) — отклонено: дублирует ссылку, добавляет таб-стоп.
- MUST: риск-пилюля показывает приоритет **находок**, а состояние версии — StatusBadge. Смешение «P0 · Карантин» в одной пилюле (S1) — отклонено.
- MUST: нет пилюли «Чисто» (S1). Если находок нет, пилюли нет; «известных уязвимостей не найдено на дату» — только в карточке пакета, где есть `scan`.
- Typosquat-предупреждение — warning-чип с иконкой и текстом «Похоже на @acme/ui — 1 символ (возможный typosquat)», ссылка на настоящий пакет.

## 7. Блок установки

**Анатомия.** Карточка «Установка» · SegmentedControl клиента (npm · pnpm · yarn / pip · uv · poetry / Maven · Gradle / dotnet / cargo), выбор запоминается per-format локально · шаг 1 «Однократная настройка» (CodeBlock `cctl login`, `cctl setup npm`) · сворачиваемое «Настроить вручную (.npmrc)» с CodeBlock, где вместо токена `${CRANE_TOKEN}`, и caption «Токен не показывается: используйте cctl или переменную окружения» · шаг 2 «Установка» (CodeBlock с версией).

**Данные.** `GET …/install?client=…` → шаги-сниппеты без секрета (сервер гарантирует).

**Правила.** MUST: ни в одном сниппете нет значения токена. MUST: кнопка «Копировать» у каждого CodeBlock с доступным именем «Копировать команду установки» и тостом/`aria-live` «Скопировано». Primary «Скопировать команду» в шапке копирует шаг 2 для выбранного клиента.

**Из макетов.** S2 — оставлено почти без изменений: это лучший блок пачки. Ссылка «Переменные окружения» в строке «Настроить вручную» — оставить как ссылку на справку.

## 8. KeyValueList и CopyableId

**Анатомия.** Лейбл (caption, text-muted) слева, значение справа; на узкой ширине — лейбл над значением. Идентификаторы (PURL, SHA-256, request_id, prev_hash) — `CopyableId` с усечением в середине «a88d…6973» и полным значением в подсказке и при копировании.

**Правила.** MUST: усечённое значение имеет полное значение в доступном имени. *Мнение:* в KV не больше 8 строк; дальше — вкладка «Метаданные».

**Из макетов.** S2 «Метаданные», S8 «Сведения об уязвимости», S9 панель события в 2 колонки — оставлено. S3: KV в рамке с разделителями — допустимо.

## 9. Бейджи состояний и флагов

| Что | Компонент | Правило |
| --- | --- | --- |
| Состояние версии | `StatusBadge` | quarantined «Карантин» (warning, часы) · released «Выпущена» (success) · blocked «Заблокирована» (error, щит) + **причина рядом** · deleted «Удалена» (neutral, версия зачёркнута, подсказка «Номер версии нельзя использовать повторно») |
| Флаги формата | outline `Badge` | yanked, unlisted, deprecated (с сообщением в подсказке), dist-tags, SNAPSHOT, «изменяемая». MUST: флаги — отдельная колонка от состояния; причина блокировки (CVE) — в колонке состояния, не в флагах (S3 — исправить) |
| Жизненный цикл пакета | `StatusBadge` | Активен · Устарел (warning, «Замена: …» ссылкой) · EOL (neutral) |
| Формат, вид репозитория | нейтральный `Badge` | «npm», «hosted»/«proxy». MUST: не раскрашивать форматы разными цветами (S7 PyPI/Maven — отклонено, цвет без смысла) |
| Среда | пилюля | PROD = error-тон, STAGE = warning, DEV = muted — только в сайдбаре и в таблице влияния, если API когда-нибудь отдаст среду (сейчас нет — см. `decisions.md`) |

Пульс статуса (3 × 1,6 с) — только у выполняющихся процессов (перенос хранилища, проверка целостности), не у «Работает».

## 10. Приоритет и SLA

**Анатомия.** Пилюля приоритета «P1 Критично» (P0 error с заполненной точкой, P1 error, P2 warning, P3 info, P4 neutral) + отдельный чип SLA («осталось 14 ч» → warning при `sla.state=warning` → error «просрочено на 2 ч» при `breached`; P4 без SLA — чипа нет). Рядом чип источника приоритета «по правилам» / «оценка systemone».

**Правила.**
- MUST: текст SLA вычисляет UI из `sla.due_at`, цвет — из `sla.state` сервера (единственный источник истины о порогах 25 %).
- MUST: обратный отсчёт в шапке находки (S8) обновляется раз в минуту, без секунд и без `aria-live` (иначе скринридер будет перебивать); точное время срока — в подсказке.
- Отклонено: «SLA 24 ч» как второй лейбл на плитке P0 (S7) — путает срок с остатком.

## 11. Карточки гейтов и вердикт продвижения

**Анатомия.** Callout-вердикт сверху: «Продвижение в release заблокировано: 2 причины» + ссылка «Политика гейтов». Ниже ряд из 4 карточек (`repeat(auto-fit, minmax(240px,1fr))`): overline названия гейта · StatusBadge результата · список причин (≤ 3, остальное «ещё N») · ссылка «Подробнее» в соответствующую вкладку.

**Результаты гейта.** passed «Пройдена» (success) · denied «Отказ» (error) · missing «Нет данных» (neutral, пунктирная рамка) · analysis_error «Ошибка анализа» (warning) · stale «Устарела» (warning, «отчёт старше базы на 31 ч»).

**Данные.** `GET …/versions/{v}/promotion?target=release` → `verdict{allowed, reasons[]}`, `gates[]`, `approvals{required, granted[], pending_request?}`.

**Правила.** MUST: пунктирная рамка у «Нет данных» — не единственный признак (есть текст). MUST: «Пересчитать» показывает результат через тост и обновляет карточки без перестройки страницы. Отклонено: английский чип «Security Gate Fail» (S4), SLA-чип внутри карточки гейта (дублирует вкладку «Находки»).

**Из макетов.** S4 — композиция оставлена целиком: вердикт → гейты → одобрения → лицензия/evidence. Это шаблон для F11, C3, D7 (вариант промоушена).

## 12. Evidence и свежесть

**Анатомия.** Список строк: тип evidence (SBOM CycloneDX 1.5, отчёт Trivy 0.58, provenance, SonarQube) · caption (версия инструмента, версия базы, «старше базы на 31 ч») · бейдж свежести справа (Свежая / Устарела / Нет данных / Ошибка анализа). Под списком — фраза об отсутствии находок с датой и версией базы (`scan`), если она применима.

**Правила.** MUST: «Известных уязвимостей не найдено на 27.10.2026, база Trivy v2026.10.27» — только при наличии `scan`; без него — «Нет данных». Порог «устарела» (24 ч от базы, SBOM 30 дней — раздел 11.5) вычисляет сервер.

**Из макетов.** S4 правая колонка «Evidence» — оставлено. «Действия над версией» (скачать SBOM, архив, сравнить) — адаптировано: скачивания SBOM, evidence и архива — в меню «…» шапки версии, через `/api` с авторизацией (ссылка `crane:content` у элемента evidence; решение 27.10.2026); сравнение — во вкладке «Метаданные». Блок «Удаление или отзыв версии» в правой колонке — отклонено (дублирует меню шапки; опасная зона в колонке справки).

## 13. Лицензия: источники, конфликт, решения по контекстам

**Анатомия.** SPDX-выражение крупно · таблица источников (ручная проверка / SBOM / метаданные / файлы; SPDX; уверенность %; где найдено) · callout «Конфликт источников» (warning) при `conflict` · «Неоднозначный идентификатор» при `ambiguous` · матрица 4 контекстов (Внутреннее · Распространение · SaaS · Встраивание) с решением Разрешена / На проверку / Запрещена · ScoreBar `license_virality` (см. 14).

**Правила.** MUST: матрица — таблица (`th` строки/столбцы), а не 4 карточки без заголовков. MUST: уверенность определения — число с «%», не цветная точка (S4 — точка цвета без смысла, исправить).

## 14. ScoreBar с уверенностью (оценки systemone)

**Анатомия.** Название оценки (exploit_relevance «Релевантность эксплуатации», blast_radius «Радиус поражения», license_virality «Вирусность лицензии») · значение «0,88» · `ScoreBar` одного тона по порогам кита (<0,5 / <0,8 / ≥0,8) · строка «уверенность 0,92» · чипы главных факторов · caption «модель systemone v3.1» · бейдж «shadow», если модель теневая.

**Правила.**
- MUST: при `confidence < 0.5` полоса muted и caption «низкая уверенность, не влияет на политику» (раздел 11.6).
- MUST: shadow-оценка визуально вторична и подписана «не влияет на решения».
- Отклонено: многоцветная градиентная полоса virality (S4), «Доверительный интервал: 0,71» (это уверенность, а не интервал), «Критический риск» как вывод модели (S8) — модель даёт сигнал, а не вердикт (раздел 13).

## 15. Четыре уровня достоверности использования

**Анатомия.** Таблица влияния: Проект · Версия · Команда · **Скачивания · Lockfile · SBOM · Развёрнуто** (четыре отдельные колонки) · над таблицей чипы-фильтры по уровню со счётчиками (`counts`).

**Правила.**
- MUST: уровни никогда не сливаются в один «уровень достоверности» (раздел 10.7).
- MUST: в ячейке не только галочка: иконка + скрытый текст «да»/«нет», в заголовке колонки — полное имя уровня (WCAG 1.1.1, 1.3.1). Прочерк «—» для «нет» допустим визуально при наличии текста для AT.
- Сводка над таблицей: «Затронуто 48 проектов, развёрнуто в 6».
- Колонка «Окружение PROD/STAGE/DEV» из S8 — не показывается, пока API не отдаёт evidence о развёртывании (решение владельца 27.10.2026).

## 16. Timeline (история)

**Анатомия.** Точка + линия · время · событие (одна строка) · опционально тег причины («по правилу», «фид», «оценка модели», «вручную») · опционально caption и ссылка (#4521, CVE).

**Правила.** MUST: цвет точки дублируется тегом или текстом. Порядок: новые сверху на страницах истории (S8), хронологически сверху вниз в жизненном цикле версии (S3). Теги на русском (S8 «AI REASONING» — исправить).

**Из макетов.** S3 «История и гейты», S8 «История приоритета» с тегами-источниками — оставлено. Это же шаблон для ротации робота (D3), бэкапов (E10), трассы Cedar (D7).

## 20. Маскирование и раскрытие ПДн

**Поток.** Таблица и панель показывают псевдоним «user-7f3a» с бейджем «Маскировано» и IP «10.12.4.0/24». Кнопка «Раскрыть данные» (бейдж MFA) в sticky-подвале панели → **модальный** Dialog: обязательное «Обоснование» (минимум 20 символов, счётчик), инлайн-уведомление «Потребуется подтверждение входа (MFA)», caption «Раскрытие будет записано в журнал» → «Раскрыть» → при 401 `required_acr` — Step-up (21) → после возврата повтор с тем же Idempotency-Key → поля в панели меняются на раскрытые с пометкой «Раскрыто вами в 14:07, записано в журнал».

**Правила.**
- MUST: раскрытые данные живут только в памяти текущей панели: не кэшируются, исчезают при закрытии панели и переходе (ответ no-store).
- MUST: аудитор и любые роли без `ссылки `crane:reveal`` кнопки не видят.
- Отклонено: диалог раскрытия как вечная карточка под панелью (S9); ссылка на ISO 27001 в шапке диалога.

## 21. Step-up MFA

**Анатомия.** Dialog 448: «Подтвердите вход» · текст «Действие „Раскрыть данные события“ требует подтверждения вторым фактором» · caption «После подтверждения вы вернётесь к действию, данные формы сохранятся» · «Продолжить в Keycloak» (primary) · «Отмена».

**Правила.** MUST: введённое в форме (обоснование) сохраняется на время редиректа (sessionStorage, очищается после повтора) — WCAG 2.2 3.3.7. MUST: никаких своих полей кода на стороне CRANE, только редирект в Keycloak (3.3.8: менеджеры паролей и вставка работают там). Отклонено: технический текст «acr: mfa», «Сессия действительна 15 минут» без источника (S9).

## 22. Массовые действия

**Анатомия.** Чекбокс-колонка (закреплена) → при выборе плавающий `BulkActionBar` снизу по центру: «Выбрано 3» · действия · ×. Ниже `md` — на всю ширину.

**Данные.** Массовое и одиночное действие — один вызов: `POST /vex-statements|/exceptions|/issues {finding_ids[]…}` → `results[{finding_id, outcome, id?, problem?}]`.

**Правила.**
- MUST: итог — тост «Создано 2 · пропущено 1 · ошибок 0» + при ошибках остаётся выделение только на неуспешных строках, у каждой — причина.
- MUST: «Принять VEX» активна, только если все выбранные находки одного advisory; иначе disabled с подсказкой «VEX выдаётся на один бюллетень» (сервер дублирует 422 `bulk-vex-single-advisory`).
- MUST: «Исключение с TTL» открывает форму (обоснование, TTL) + MFA; не выполняется в один клик.
- MUST: панель не перекрывает последнюю строку таблицы и элемент в фокусе (отступ снизу = высота панели; WCAG 2.2 2.4.11).
- Отклонено: «Экспорт» в bulk-панели (S7) — экспорт находок не описан в продукте.

## 25. Баннеры (глобальные)

**Порядок важности.** 1) P0 без действия > 1 ч (error, только AppSec/SecOps) · 2) Только чтение (warning) · 3) SoD warn (warning, без имён) · 4) Upstream недоступен / stale (warning) · 5) Ассистенты недоступны (info).

**Анатомия.** Иконка · текст «что случилось и что это значит для вас» · одна ссылка-действие справа. Не закрываются, пока состояние активно (кроме info — сворачивается до следующей сессии).

**Правила.** MUST: появление нового баннера объявляется `role="status"`; P0 — `role="alert"` один раз. MUST: не больше двух видимых. Отклонено: баннер SoD с ФИО (S10) — ПДн в глобальной зоне; «fallback: BM25 active», «Mirror retry: 45s» (техножаргон).

## 27. Системные состояния

| Состояние | Компонент кита | Обязательное содержимое |
| --- | --- | --- |
| Загрузка | `Skeleton` (8 строк таблицы / плитки) | Не раньше 300 мс; > 1 с — скелетон, а не спиннер. Скелетон повторяет сетку, CLS = 0 |
| Пусто (первый запуск) | `EmptyState` | Иллюстрация в графитовых тонах · что здесь будет · одно primary («Как опубликовать») · опционально secondary («Импорт из Nexus») |
| Пусто (фильтр) | `EmptyState` compact | «Ничего не найдено по фильтрам» · «Сбросить фильтры». Без иллюстрации |
| Ошибка problem+json | `ErrorState` | `title` · `detail` · «Правило: <rule_id>» · `request_id` (`CopyableId`) → «Диагностика» · нумерованные `remediation[]` · «Повторить» (если идемпотентно) |
| Отказ (403) | `SystemState kind="forbidden"` | Только для **видимого** ресурса, где запрещено действие: «Недостаточно прав» · «Правило: <rule_id>» · request_id · контакт (`contact`) · `remediation[]` · «Запросить доступ» |
| Не найдено или нет доступа (404) | `SystemState kind="not-found"` | MUST: один и тот же нейтральный экран для несуществующего и скрытого: «Не найдено или нет доступа» · «Проверьте адрес или имя пакета» · поиск · «На главную». Без правила, контакта, «Запросить доступ» и подсказок о существовании; request_id — можно (он не выдаёт ресурс) |
| Нет сети / сессия | `SystemState offline|session` | Последние данные остаются, действие «Войти снова» |
| Только чтение | баннер + disabled мутаций с причиной | |

Отклонено: HTTP-код как подпись («HTTP 413 Payload Too Large», S10) — пользователю нужен смысл, код — в «Диагностике». Трасса политик на экране отказа (S10.5) — только на странице «Диагностика» (согласовано с API: трасса может выдать существование ресурса). Чужой или скрытый `request_id` в «Диагностике» даёт тот же нейтральный 404.
