# А. Глоссарий

| Термин | Определение |
| --- | --- |
| **A2A** | Agent2Agent: открытый протокол взаимодействия агентов (JSON-RPC over HTTPS, Agent Card, задачи со статусами). CRANE предоставляет собственного A2A-агента для чтения и управляемой записи. |
| **Attestation** | Подписанное утверждение о файле версии (in-toto Statement в DSSE, Sigstore bundle): кто, из какого репозитория и коммита собрал или что проверил. CRANE проверяет подпись, издателя и совпадение digest с blob. |
| **Back-Channel Logout** | Стандарт OIDC: Keycloak сообщает приложению о завершении сессии пользователя напрямую, без браузера. |
| **Blast radius** | Масштаб возможного ущерба от уязвимости: сколько потребителей, приложений и команд затронуто и насколько они критичны. |
| **CAS** | Content-addressable storage: объект хранится по хэшу содержимого, одинаковые файлы хранятся один раз. |
| **Cargo sparse registry** | Протокол реестра крейтов Rust по HTTP (RFC 2789): `config.json`, индекс в виде файлов NDJSON на крейт, скачивание `.crate` по шаблону `dl`. Заменяет git-индекс; единственный вариант, который реализует CRANE. |
| **Cedar** | Язык и движок политик авторизации (Apache-2.0), возвращает решение и сработавшие правила. |
| **CSAF** | Common Security Advisory Framework: машиночитаемый формат advisory и VEX от поставщиков. |
| **Dependency confusion** | Атака, при которой публичный пакет с внутренним именем подменяет внутренний. |
| **Device Authorization Grant** | Поток OIDC для устройств без браузера (RFC 8628): CLI показывает код, пользователь входит с другого устройства. |
| **EPSS** | Exploit Prediction Scoring System (FIRST): вероятность эксплуатации уязвимости в ближайшие 30 дней. |
| **Evidence** | Доказательство о версии: SBOM, отчёт сканера, attestation, подпись файла. Вид определяет `predicate_type`, происхождение — `trust`, подписанность — `verify_result`; новый вид не меняет схему. |
| **GCRA** | Generic Cell Rate Algorithm, точный алгоритм ограничения частоты с одним числом состояния. |
| **KEV** | Known Exploited Vulnerabilities (CISA): каталог уязвимостей, эксплуатируемых на практике. |
| **LLM** | Генеративная языковая модель. В CRANE пишет объяснения, сводки и разбирает намерение в A2A-агенте; решений не принимает. |
| **OCSF** | Open Cybersecurity Schema Framework: открытая схема событий безопасности; основной формат экспорта в SIEM. |
| **OSV** | Open Source Vulnerabilities: открытый формат и агрегатор advisory по экосистемам, включая вредоносные пакеты. |
| **Outbox** | Таблица событий, записываемая в той же транзакции, что и данные; гарантирует доставку без потерь. |
| **Packument** | Документ metadata npm-пакета со списком версий. |
| **PURL** | Package URL: универсальный идентификатор пакета для всех экосистем. |
| **RRF** | Reciprocal Rank Fusion: объединение ранжированных списков разных поисков. |
| **SBOM** | Software Bill of Materials (CycloneDX, SPDX): состав зависимостей артефакта. |
| **Sigma** | Открытый формат правил обнаружения, переводимый в язык запросов конкретной SIEM. |
| **Singleflight** | Объединение конкурентных одинаковых запросов в одну операцию. |
| **Slopsquatting** | Регистрация атакующим пакета с именем, которое придумала LLM, в расчёте на то, что его установят по совету модели. |
| **SOAR** | Security Orchestration, Automation and Response: платформа автоматизации реагирования на инциденты. |
| **SWR** | Stale-while-revalidate: отдача устаревшего значения с фоновым обновлением. |
| **systemone** | Совместимый API скоринговых моделей (например, JEV). Модели возвращают числовые оценки риска с уверенностью и факторами: `exploit_relevance`, `blast_radius`, `license_virality`. Подключаются через порт `RiskScorer`. |
| **Token Exchange** | Обмен токена одного издателя на токен другого (RFC 8693); в CRANE OIDC-токен платформы меняется на краткоживущий `crci_`. |
| **VEX** | Vulnerability Exploitability eXchange: заявление о том, применима ли уязвимость к продукту (`not_affected`, `affected`, `fixed`, `under_investigation`). |
| **Workload identity** | Аутентификация CI job по подписанному токену платформы вместо хранимого секрета. |
| **Вирусность лицензии** | Степень, в которой обязательства лицензии распространяются на производное ПО в данном контексте; оценивается моделью systemone как `license_virality`. |
| **Класс хранения** | Логическое назначение хранилища blob (`primary`, `proxy-cache`, `archive`, `restricted`), указывающее на физическое хранилище. |
| **Приказ ФСТЭК № 21** | Состав и содержание мер по защите персональных данных в информационных системах; детализирует требования 152-ФЗ. |
| **Разделение обязанностей** | Separation of duties (SoD): одна роль не может и выполнять действия, и контролировать их журнал. |
