# 19. Риски и открытые решения

## Риски

| Риск | Влияние | Митигирование |
| --- | --- | --- |
| Перенос нормы с эталона на Rust и другой домен | Высокое | Замер скорости на первой неделе P0 и пересчёт `tools/estimate-agent-hours.py`; пессимистичный сценарий заложен в план (раздел 18) |
| Ревью оператора становится узким местом | Среднее | Ревью по риску: лично только критичные модули; остальное через автоматические проверки и мутационное тестирование; второй ревьюер на P2 |
| Совместимость протоколов (NuGet V3, Cargo sparse и credential providers, Maven SNAPSHOT, клиенты разных версий) | Высокое | Матрица реальных клиентов в CI с первого спринта; спайки в PoC; ранние пилотные команды |
| Ожидание «девяти девяток» доступности | Среднее | Согласовать SLO по разделу 4 до старта; разделить durability и availability |
| Нагрузка и безопасность подтверждаются только после v1 | Среднее | Модель угроз и мутационный порог на критичном пути, cargo-deny и cargo-audit в CI, публичный `SECURITY.md`; пентест (Strix) и нагрузочный стенд идут на этапе «После v1» (ROADMAP) |
| Зрелость RustFS | Низкое | SeaweedFS по умолчанию; хранилище подменяемо без изменения кода |
| Нагрузка на AI-контур при индексации | Низкое | Пакетная индексация, лимиты, кэш эмбеддингов по хэшу текста |
| Поток уязвимостей растёт быстрее, чем его разбирают люди | Высокое | Автоматическое сопоставление по PURL, приоритет P0–P4, дайджесты вместо писем на каждый finding, VEX и автозакрытие, метрика нарушений SLA в SIEM |
| Ошибки или дрейф моделей systemone | Среднее | Оценка только ужесточает решения; теневой режим новых версий; калибровка по доле переопределений; без модели работают правила |
| Недоступность генеративных моделей | Низкое | Резервный провайдер, circuit breaker, деградация до лексического поиска и структурированных ответов |
| Условия использования фидов уязвимостей | Низкое | Проверить лицензии и лимиты OSV, GHSA, NVD, KEV, EPSS до релиза; хранить источник каждого поля advisory |
| Ошибочная запись через A2A-агента | Среднее | Двухфазная запись с подтверждением плана, ограниченный набор обратимых навыков, аудит канала `a2a`, раздельные scopes |
| Качество данных о потребителях и деплоях | Среднее | Явные уровни достоверности; источник deployment evidence согласовать на P3 |
| Администратор платформы получает доступ к журналу действий | Среднее | Разделение обязанностей в режиме `strict`, событие `sod.violation` в SIEM, роль БД без UPDATE и DELETE (раздел 14.12) |
| Юридическая трактовка лицензий | Среднее | Продукт не выносит вердиктов; политика задаётся организацией, неоднозначные случаи уходят на review |
| Без каталога и push роль, снятая в IdP, живёт до следующего входа | Среднее | Потолок `crp_` при отсутствии каталога и push `session_ttl_without_directory` (по умолчанию 1 ч вместо 12 ч); для Keycloak включить опрос Admin REST и admin events, для остальных SCIM; отчёт о пересмотре доступа показывает «наблюдалось в момент» (13, 14.15) |

| 13 | Сертификация ФСТЭК | Продукт не сертифицирован. Для ГИС и значимых объектов КИИ, где нужны сертифицированные средства, решать отдельно: сертификация сборки или компенсирующие меры по решению оператора. |
| 14 | Event listener в Keycloak | Профиль Keycloak: расширение с HTTP-доставкой admin events, блокировка применяется за секунды; без него — опрос Admin REST раз в 5 минут; другие IdP — SCIM или TTL (решение 34). |
| 15 | Cargo | Поддерживается только sparse-протокол (`sparse+https://`), git-индекс не реализуется. Первыми потребителями становятся внутренние крейты CRANE (dogfooding). Версию cargo в матрице клиентов фиксировать как «две последние стабильные». |
| 16 | Очередь задач и транзакции в портах | Принято: типа `Tx` в портах нет. Атомарные методы каталога принимают задачи данными (`publish_version(new, jobs: &[NewJob])`, параметр появляется с первой задачей), адаптер пишет данные и строки `job` в одной транзакции. Порт `JobQueue` только для потребителя: `claim(kinds, n, lease) -> Vec<Claimed>`, `complete(Claimed)`, `fail(Claimed, error)`, где `Claimed` не `Clone` и несёт id, kind, payload и attempt (токен владения), как `Staged` в `BlobStore`; после истечения lease задача может выполниться повторно, обработчики идемпотентны. Таблица `job` с visibility timeout (`run_at`, `attempts` как токен владения, удаление выполненных, `job_dead` для исчерпанных), пробуждение через NOTIFY и опрос. Outbox с relay только для внешней доставки (webhooks, SIEM): решается в P2 / v1.1.0. Инвалидация кэша metadata в v0.2.0: прямая после commit, TTL как страховка. |
| 17 | Безопасность важнее приватности | Принято владельцем 27.10.2026. Журнал действий и поток скачиваний хранят реальные идентификаторы внутри защищённых от подмены структур; стирания по субъекту и псевдонимизации «для удаления» нет. Целостность и атрибуция перед лицом атакующего важнее права на стирание: удаление только по сроку хранения, целыми периодами. Удаление по GDPR (ст. 17) не поддерживается, развёртывания под GDPR оценивают это сами. Маскирование в UI остаётся как мера доступа (14.13). |
| 18 | Чистый OSS без обязательств | Принято владельцем 27.10.2026. CRANE всегда остаётся чистым OSS и не будет продан; один maintainer, без SLA, без гарантированного срока поддержки, без команды безопасности. Исправления идут в последний релиз, бэкпорты по возможности. Безопасность релизов best effort: SLSA provenance, cosign, SBOM, CSAF/VEX по возможности. CRANE — некоммерческое свободное ПО и не выводится на рынок в ходе коммерческой деятельности (п. 18 преамбулы Регламента (ЕС) 2024/2847, CRA), поэтому обязанности производителя проект на себя не принимает; кто поставляет CRANE в коммерческом продукте, оценивает свои обязанности сам. Это не юридическая консультация. См. [SECURITY.md](../../.github/SECURITY.md). |

| 45 | Размер файлов и функций | Принято 28.10.2026 (be-lead, обратимо; владелец пересматривает). Выбор: большие файлы запрещены. Файл ≤ 400 физических строк (как считает `wc -l`; `.rs`, `.ts`, `.tsx`, тесты и комментарии включены; корни `crates`, `web/src`, `web/screens`, `web/test`, `cli`, `tools`; кроме `generated/` и `migrations/`), нарушение — ошибка `lint-structure`; предупреждение с 320 строк (80%) в `task structure:report`. Вынесенные юнит-тесты Rust — `tests/<файл>.rs` рядом с модулем через `#[path]`; большой интеграционный тест — папка `tests/<имя>/main.rs`, а не новый бинарь; тесты TS — `x.<предмет>.test.ts`, общие помощники — `x.fixtures.ts`. Данные на момент решения: файлов > 400 было 24 в `crates`/`web/src`/`tools` (самый большой `config/mod.rs`, 1765 строк) и ещё 6 историй в `web/screens` (самая большая 693). Функции: clippy по умолчанию (через pedantic) допускал 100 строк, нарушителей 0; при 60 — 4 (`app/proxy/lead` 87, `pg publish_version` 95, `npm publish` 68, тест `npm packument` 62), при 50 — 11, при 40 — 24. Biome при 80 (без пустых, тесты выключены) — 3 (`DataTable.tsx` 93, `dogfood/cargo.ts` 87, `dogfood/stand.ts` 94), при 60 — 6 нетестовых, включая screens; все исправлены в этом рефакторинге. Отвергнуто: счёт «значимых» строк (наказывает комментарии «почему» и склеивается), отдельный лимит для тестов, ESLint `max-lines` (второй линтер), имя `MountSettings` (слово mount занято в `crates/entry/http`; вместо него `Repos` с `RepositoryKind`). Откат: поднять пороги в `tools/lint-structure/rules.json`, `clippy.toml`, `biome.json`. |
| 46 | Отказ PostgreSQL и скачивания из кэша | Принято владельцем 28.10.2026. При недоступном каталоге все протокольные запросы, включая proxy-чтения и попадания в кэш, получают `503 Retry-After: 10` без выборок из upstream (fail closed): без каталога не проверить резервации и namespaces hosted, экстренные блокировки и quarantine (H4), а имя из upstream или кэша открывает typosquatting и dependency confusion. Безопасность важнее доступности (14, решения 17 и 28). Отвергнуто: «скачивания из кэша при отказе PG» (прежняя формулировка раздела 4). Отказ хранилища, а не баг, различается: баг остаётся `500`. Откат: нет без отдельного решения владельца; узкое исключение только по предложению, если окажется безопасным. |
