# 2. Цели, принципы и границы

## Цели и как архитектура их закрывает

| Цель | Архитектурный ответ |
| --- | --- |
| Удобство для всех ролей | Ролевые рабочие столы в UI; объяснимые решения доступа (policy trace); готовые CI templates; CLI `cctl` с командой `diag <request-id>`. |
| Скорость работы | Горячий путь скачивания не ходит в БД: двухуровневый кэш (в процессе + Valkey), потоковая отдача из S3, предвычисленные metadata с ETag. |
| Низкая нагрузка | Rust без GC, content-addressable хранение с дедупликацией, coalescing конкурентных запросов к upstream, сканирование SBOM вместо повторного сканирования байтов. |
| Огромное число запросов | Stateless API-реплики, масштабирование по RPS; запись и чтение разделены; деградация в read-only при отказе primary БД. |
| Интеграции | Версионируемый REST API с OpenAPI, подписанные webhooks через transactional outbox, события безопасности в SIEM по схеме OCSF и ответные действия SOAR, фиды уязвимостей, A2A-агент для внешних агентов, адаптеры Keycloak, GitLab, Trivy, SonarQube, AI-контура (скоринг systemone и LLM). |
| Реакция на уязвимости | Фиды OSV, GHSA, NVD, KEV, EPSS; сопоставление по PURL без пересканирования; приоритет P0–P4 с оценками systemone; экстренная блокировка; SLA и метрики (раздел 14). |
| От соло до корпорации | Один бинарник, три профиля (S/M/L), все внешние зависимости кроме PostgreSQL опциональны в профиле S. |

## Архитектурные принципы

- **P1. Модульный монолит, а не микросервисы.** Один процесс, жёсткие границы модулей (крейты — слои гексагона, bounded context — модули внутри слоёв), общение модулей через трейты и доменные события. Масштабирование ролями процесса (serve, worker), а не разрезанием на сервисы.
- **P2. Ports & Adapters вместо плагинов.** Ядро зависит только от трейтов: FormatProtocol, BlobStore, Cache, JobQueue, Scanner, AiProvider. Реализации вкомпилированы. Нет динамической загрузки кода, нет runtime-API для сторонних расширений.
- **P3. Хранение отделено от видимости.** Байты лежат в CAS по SHA-256 и не меняются. Доступность версии клиенту определяется состоянием версии и политиками. Promotion меняет метаданные, а не байты.
- **P4. Default deny и объяснимость.** Каждый запрос проходит авторизацию; каждое решение имеет trace: какое правило сработало и почему. Неизвестная лицензия означает «нужна проверка», а отсутствие CVE не означает «безопасно».
- **P5. PostgreSQL как единственный источник истины.** Valkey и S3-кэш proxy можно потерять без потери данных. Очередь задач (`job`) и outbox для внешней доставки живут в PostgreSQL, поэтому минимальный профиль не требует брокера.
- **P6. Совместимость со стандартными клиентами.** Протоколы реализуются по спецификациям, проверяются автоматической матрицей реальных клиентов (npm, pnpm, yarn, pip, uv, poetry, Maven, Gradle, dotnet, nuget.exe, cargo).

## Инженерные правила

Решения о том, как строится и выпускается код. Подробности: [раздел 8](08-c4-l4-code.md), [раздел 15](15-frontend.md), [раздел 16.7](16-deployment.md).

- **Архитектура кода.** Rust: DDD + hexagonal + clean architecture, зависимости только внутрь. Web: Feature-Sliced Design.
- **Правило четырёх.** Не больше 4 файлов и 8 подпапок в папке, смешанные папки запрещены. Проверяется линтером структуры.
- **Тесты.** Юнит-тесты на каждое изменение поведения; тесты по AAA и только на логику (проверяет `task structure`); мутационное тестирование (cargo-mutants, Stryker) на критичном пути. Полный гейт идёт локально перед PR в релизную ветку.
- **Коммиты.** Conventional Commits, проверяет commitlint. Атрибуция ИИ-агентов в коммитах и PR запрещена.
- **Выпуск.** `main` — production; `release/vX.Y.Z`; версия, CHANGELOG и тег ставятся автоматически после слияния в `main`.

## Границы первой версии

Соответствуют исходным требованиям. Не входят: собственный Git и CI, замена SonarQube и Trivy, собственные исследования уязвимостей (CRANE агрегирует открытые фиды), исполнение кода пакетов, active-active и геореплика, дополнительные форматы, автоматические юридические и security-решения моделью. Grouped endpoint (единый адрес hosted+proxy) заложен в маршрутизации, но включается после P3.
